## 観察

### 数値から言えること

- **Jev は τ=0.5（ほぼ素の argmax）で、3回とも 20/20 正解した。** LLM は3回中2回、取りこぼしが1件ずつあった（正解率 95% / 95% / 100%）。
- **search と direct の確率がはっきり分かれている。** 要検索の質問で p(direct) が最も高かったのは「前に書いた記事だと GPU メモリの設定ってどうしてましたか？」の 0.29。直接回答でよい質問で最も低かったのは「1024 × 768 はいくつになりますか？」の 0.52〜0.59。**0.29 と 0.52 の間に隙間がある**ので、τ を 0.3〜0.5 のどこに置いても全問正解になる。
- **τ を上げても取りこぼしは 0 のまま、過剰発火だけが増える。** τ=0.9 で過剰発火 1〜2 件、τ=0.99 で 5〜6 件。0001 の「迷ったら検索」を数値で表した形になっており、意図どおり**許容される側の失敗だけが増える**。
- **同じ問題に対する揺れが小さい。** p(direct) の振れ幅は最大 0.07 で、0.5 をまたいだ問題は無い。LLM は2問で判定が割れた（「infinity ってなんで使ったんだっけ？」「トークンとは何ですか？」）。
- 速度は LLM 1.8 秒に対して Jev 0.17 秒（約10倍）。60回で $0.0035。

### 定性的な観察

- **LLM が割れた2問は、Jev でも「迷っている側」に入っている。** 「トークンとは何ですか？」の p(direct) は 0.17〜0.19、「infinity ってなんで使ったんだっけ？」は 0.06〜0.08 で、他の要検索の質問（0.00〜0.01）より明らかに高い。**LLM が迷う問題では、Jev の確率も中間に寄る**。見ている難しさは同じで、違うのは、Jev はそれを確率として外に出してくれる点。
- **「計算」が direct 側でいちばん自信がない（0.52〜0.59）。** 数字が含まれていて、description の「数値が1つでも含まれるなら検索」に引っかかりかけている。閉じたリストには「6. 文書を参照しない純粋な計算」があるが、検索側の「数値が1つでも」と真っ向からぶつかる。LLM は迷わず direct を選んだので、**ルール同士の衝突に Jev の方が敏感**ということになる。
- **jev-hello では間違えたのに、ここでは正解した。** jev-hello のケース2では、中立の短い criteria で「Slurm」「トークン」を direct と判定した。今回は本番の description（「迷ったら検索」「技術用語が1つでも含まれれば検索」）を入れたことで、0.05 と 0.17〜0.19 に下がった。**判断基準の文章がそのまま効く**というケース6の観察と一致する。

### 注意

- 20件しかなく、LLM もすでにほぼ満点なので、差は1〜2件分でしかない。「Jev の方が正確」と言うには足りない。言えるのは「**同じ description で同等以上の判定ができ、さらに確率が付いてくる**」まで。
- τ をこの20件で選んでいるので、汎化性能としては楽観的（train-on-test）。実運用では別の質問セットで τ を決める必要がある。
- 0001 の初回実験（Recall 82%）より LLM が良くなっているのは、その後に description と `SKILL_SELECTION_POLICY` を改訂したため。
